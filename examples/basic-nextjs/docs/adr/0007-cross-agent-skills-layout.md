# ADR 0007: One canonical skill layout for Claude Code, Cursor, and Pi

## Status

Proposed (2026-10-06). Implementation plan: [plan-agent-skills-restructure.md](plan-agent-skills-restructure.md).

## Context

The demo builder's AI layer was authored for Claude Code first and copied by hand for Cursor:

- Canonical skill text lives as flat files in `docs/ai/skills/*.md`; `.claude/skills/` and `.cursor/skills/` hold hand-written pointer wrappers that have drifted (Claude is missing 5 skills, Cursor 4).
- `CLAUDE.md` `@`-imports six rule files. Pi does not expand `@imports`, so Pi sees only paths. `.cursor/rules/*.mdc` are stale hand copies.
- Pi discovers none of the skills (it reads `.agents/skills/`, `.pi/skills/`, or configured paths).
- MCP servers are declared only in `.mcp.json` (Claude). Cursor and Pi read `.cursor/mcp.json` and `.pi/mcp.json`. Pi normalises `-` to `_` in tool IDs, so skills that hardcode `mcp__sitecore-marketer__…` break in Pi.
- `site-analyzer` and `content-scraper` are Claude-only subagents; Pi has no built-in subagents.
- The repo-root `CLAUDE.md`/`Agents.md` are loaded by Claude and Pi when walking up the tree, and contradict this app's rules (props sidecars, `fields.data.datasource` everywhere).
- Nothing validates any of this, so drift went unnoticed. Several scripts are dead, some skills are one-shot orchestrators whose output already exists, and `.pi/` (holding `auth.json`) is not gitignored.

## Decision

1. **Canonical skills** live in `examples/basic-nextjs/.agents/skills/<name>/SKILL.md` (Agent Skills spec), each with its own `scripts/`, `references/`, `assets/`. Pi discovers them natively.
2. **Claude Code and Cursor get generated pointer wrappers** (`.claude/skills/<name>/SKILL.md`, `.cursor/skills/<name>/SKILL.md`) containing the canonical frontmatter and one line: "Read and follow `.agents/skills/<name>/SKILL.md`". Generated by `npm run agents:sync`; `--check` fails on drift. No symlinks (Windows-hostile).
3. **Scripts:** single-owner scripts live in their skill's `scripts/`. Search verification scripts form a new `sitecore-search` skill. Cross-cutting tools (sync, lint, eval, validators, setup) live in `tools/agents/` and are invoked only via `npm run agents:*`.
4. **Subagents become skills** with a strict file-in → file-out contract (`sitecore-analyze-site` → `build-plan.yaml`; `sitecore-map-content` → `content-map.yaml`). Skills flagged `metadata.subagent: true` also get a generated `.claude/agents/<name>.md` so Claude Code delegates; Pi and Cursor run them inline. `sitecore-build-demo` says: delegate if a subagent exists, else load inline.
5. **Rules:** a slim hand-written `AGENTS.md` (~80 lines: project identity pointers, router, hard non-negotiables, map of `docs/ai/`). `CLAUDE.md` contains only `@AGENTS.md`. Detailed standards move into a `sitecore-standards` skill's `references/`. `.cursor/rules/` are generated (one always-apply pointer + a glob-scoped rule for `src/components/uiim/**`). The repo-root `CLAUDE.md`/`Agents.md` are trimmed to repo-generic guidance so they no longer contradict this app (fork-only change).
6. **MCP:** canonical `.agents/mcp.json`; `agents:sync` generates `.mcp.json`, `.cursor/mcp.json`, `.pi/mcp.json`. Servers are renamed `sitecore_marketer` and `sitecore_docs` so prefixed tool IDs are identical across tools; skill text still refers to tools by plain name. `.gitignore` ignores `.pi/*` except `settings.json` and `mcp.json`.
7. **Invocation:** orchestrators and subskills are command-only (`disable-model-invocation: true`, translated per tool): `sitecore-build-demo`, `sitecore-abm-page`, `sitecore-analyze-site`, `sitecore-map-content`. All others route automatically via the `AGENTS.md` router. In-skill approval gates are kept.
8. **Inventory (15 skills), with `sitecore-` prefix kept for namespacing:**
   `sitecore-build-demo`, `sitecore-analyze-site`, `sitecore-map-content`, `sitecore-extract-theme`, `sitecore-demo-variants`, `sitecore-create-simple`, `sitecore-create-list`, `sitecore-create-context`, `sitecore-create-page-template`, `sitecore-add-variants`, `sitecore-diagnose-rendering`, `sitecore-manifest`, `sitecore-search`, `sitecore-abm-page`, `sitecore-standards`.
   - Merged: `fix-componentquery` + `fix-datasource-picker` → `sitecore-diagnose-rendering`; `maintain-manifest` + `validate-manifest` → `sitecore-manifest`.
   - Retired: `create-article-page`, `create-landing-page` (output exists; kept as worked examples in `sitecore-create-page-template/references/`).
   - Parameterised: ABM campaign/event details move to `sitecore-abm-page/references/campaign.yaml`.
   - Deleted: `download-images.mjs`, `validate-types.mjs`, `search-debug.mjs`, `apply-variants.mjs`, hand-written wrappers/rules, `copilot-instructions.md`, `Skills.md`, `.clinerules/`, `.cline/` (app level).
9. **`docs/ai/` keeps project knowledge and state** (`config/`, `manifests/`, `catalog/`, shared `reference/`, `designs/`, gitignored `demos/` and `themes/*/`). Anything used by exactly one skill moves into that skill. Test: *would I delete it if I deleted the skill?* Skills reference `docs/ai/…` by app-root-relative path.
10. **Guardrails:** `agents:sync --check` and `agents:lint` run in pre-commit and CI. `agents:lint` validates frontmatter, referenced paths and npm scripts, forbidden patterns (prefixed MCP IDs, old `docs/ai/skills|scripts` paths, `@` imports in `AGENTS.md`), and router ↔ skill set consistency. Routing evals (`tools/agents/evals/routing.yaml`, from `TEST-PROMPTS.md`) run manually via `npm run agents:eval`.
11. **Rollout:** five phased PRs (tooling & security → pure move → rules → consolidation → cleanup & evals).

## Alternatives considered

- **Canonical in `docs/ai/skills/`** — human-visible, but Pi then depends on `settings.json` + project trust, and Claude/Cursor still need wrappers.
- **Repo-root `.agents/skills/`** — skills are basic-nextjs-specific; Claude/Cursor launched from the app would not see them.
- **Symlinks** — zero drift, but break on default Windows clones; SEs ship `setup.ps1`/`setup.cmd`.
- **Full copies per tool** — three copies of every script; edits land in the wrong copy.
- **Concatenated ~700-line `AGENTS.md`** — guaranteed consistency but heavy always-on context.
- **Pi subagent extension** — real isolation in Pi only; deferred until context pressure proves it necessary.
- **Big-bang PR / long-lived branch** — unreviewable, and painful for demo branches that rebase on `main`.

## Consequences

- One edit point per skill; three tools stay in sync mechanically.
- Pi works after phase 1 (MCP) and phase 2 (skills).
- Wrappers add one file read per skill load in Claude/Cursor.
- Claude Code keeps subagent isolation; Pi/Cursor run analysis inline and use more main-context.
- MCP server rename requires each user to re-authenticate once per tool.
- Demo branches absorb the change gradually; phase 2 is mostly git renames.
- Root `CLAUDE.md`/`Agents.md` diverge from upstream — accepted, this is a fork.
