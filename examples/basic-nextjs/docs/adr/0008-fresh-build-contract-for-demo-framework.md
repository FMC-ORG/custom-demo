# ADR 0008: Fresh build contract for the demo-framework changes

The demo-framework changes in items 1, 5, 8 and 9 introduce mandatory shared Header/Footer datasource wiring, batch-wide Content Hub verification windows and potentially creation-time field values. We require a fresh workspace and approved build scope for the changed pipeline rather than migrating older incomplete builds: migration would add write targets or alter issued-operation arguments beyond their original approval. Older incompatible records must be detected and rejected before mutations, with their checkpoints and remote resources preserved; a new directory is not permission to duplicate matching remote content or delete old resources. Interrupted builds created under the new contract retain normal same-workspace recovery and no-blind-retry safeguards. This is an intentional pipeline compatibility boundary, not a prohibition on existing content consuming the font/visibility fixes, and it does not retroactively change the separately implemented backward-compatible repeated-read performance fix.

Decision source: [demo-framework interview, decision 9](../ai/backlog/demo-framework-fixes-1-5-8-9.md#confirmed-interview-decisions). No migration, live reset, cleanup, or implementation is authorised by recording this decision.
