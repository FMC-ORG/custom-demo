# Sitecore Starter sync runbook

Repeatable process for bringing the Sitecore Starter's `examples/basic-nextjs` changes into this project. Rationale: [ADR 0010](./0010-port-sitecore-starter-changes-instead-of-merging.md). The **Sitecore Starter** is `Sitecore/xmcloud-starter-js`. Never call it "upstream": here the git remote `upstream` is the FMC-ORG framework repository.

## When to sync

- On meaningful Sitecore releases: a Content SDK minor/major version, Next.js support changes, or new Sitecore features in `basic-nextjs`.
- Not for Dependabot-only or CI-only commits.

## 1. Find what changed

Run from the repository root. This fetches without adding a remote:

```bash
git fetch https://github.com/Sitecore/xmcloud-starter-js.git main:refs/sitecore/main
SYNCED=$(grep '^syncedCommit:' examples/basic-nextjs/docs/ai/config/upstream-sync.yaml | awk '{print $2}')
git log --oneline $SYNCED..refs/sitecore/main -- examples/basic-nextjs
git diff --stat $SYNCED refs/sitecore/main -- examples/basic-nextjs
# Files we changed too (manual merge):
comm -12 <(git diff --name-only $SYNCED refs/sitecore/main -- examples/basic-nextjs | sort) \
         <(git diff --name-only $SYNCED HEAD -- examples/basic-nextjs | sort)
```

Compare the Sitecore packages and versions:

```bash
git show refs/sitecore/main:examples/basic-nextjs/package.json | grep -E 'sitecore|"next"|typescript'
npm view @sitecore-content-sdk/nextjs version   # latest
```

## 2. Branch

Feature branch from `main` (`git switch -c feature/sitecore-starter-sync-<version> upstream/main`), PR to `dmz`, as for any change.

## 3. Port, file by file

| Situation | Action |
|---|---|
| Changed only by Sitecore | Take Sitecore's version: `git checkout refs/sitecore/main -- <path>` |
| Changed by both | Merge by hand using the ownership rules below |
| Changed only by us | Keep ours |
| Outside `examples/basic-nextjs` (other starters, `.github/`, `authoring/`, `local-containers/`) | Do not take (ADR 0010) |

Ownership for files changed by both:

| File | Rule |
|---|---|
| `package.json` | Sitecore's SDK, Next.js and TypeScript versions (latest within the current major); keep all our extra dependencies and scripts |
| `package-lock.json` | Never merge. Delete and regenerate with npm 11 (`npx -y npm@11 install`) |
| `sitecore.cli.config.ts` | Union of both exclusion lists |
| `src/Layout.tsx` | Sitecore's SDK types; keep our page-field types |
| `next.config.ts` | Sitecore's structure; keep our rewrites and image domains |
| `.sitecore/component-map.ts` | Ours; regenerate with the CLI and keep only Sitecore renderings |
| `next-env.d.ts` | Generated by Next.js; do not hand-edit |
| `src/components/uiim/**`, `.agents/**`, `docs/**`, `tools/**` | Ours |

## 4. Check

- `npm run type-check` (offline fixtures: `node tools/ci/prepare-typecheck.cjs`), `npm test`, `npm run agents:check`, `npm run agents:validate`, `npm run lint` (no new errors).
- Against Sitecore, with a `.env` whose Edge context ID works for the demo environment:
  - production build (`npx -y npm@11 run build`; npm 12 rejects the `config` flags passed by `npm-run-all`);
  - dev server: Home and an Article page render with UIIM components;
  - page `<head>` tags (title, description, Open Graph) compared before/after;
  - `/llms.txt`, `/sitemap.xml`, `/robots.txt`, `/ai/service.json` respond;
  - the three `sitecore-search` verification scripts pass.
- Quick Edge check before blaming the code: a plain layout query to `edge-platform.sitecorecloud.io` with the `.env` context ID must not answer "No sitecore context". Next.js may otherwise serve cached content from `.next/`.

## 5. Record and deliver

1. Update `docs/ai/config/upstream-sync.yaml`: `syncedCommit`, dates, `versions`.
2. PR to `dmz` (squash), listing versions before/after, behaviour changes and check results; then promote `dmz` to `main` with a merge commit.

## Rollback

Revert the squash commit on `dmz` (or the promotion merge on `main` with `git revert -m 1`). The recorded `syncedCommit` reverts with it.

## Known traps (October 2026 sync)

- Tailwind ≥ 4.3.3 turns example class strings in docs (e.g. `font-[var(...)]`) into invalid CSS; `globals.css` restricts scanning to `src/` with `source('../')`.
- Tailwind's compiler registers Node module hooks that Jest's sandbox refuses; compile CSS in a child process in tests.
